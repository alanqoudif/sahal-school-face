# سهل — نظام حضور الطلاب

نظام ويب بسيط يسجّل حضور الطلاب بالتعرف على الوجه. تضيف صور الطلاب وبياناتهم، ولما يمر الطالب قدام كاميرا اللابتوب ينسجل حضوره مرة واحدة في اليوم.

## المتطلبات

- بايثون 3.10 أو أحدث (يُفضّل 3.12)
- كاميرا في اللابتوب أو كاميرا USB
- اتصال إنترنت لأول تشغيل فقط (لتحميل مكتبة التعرف)

## التشغيل

من مجلد المشروع:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

ثم افتح المتصفح على [http://127.0.0.1:8000](http://127.0.0.1:8000)

كلمة دخول الإدارة الافتراضية `sahal`. غيّرها عبر `SAHAL_ADMIN_PASSWORD` قبل التشغيل على سيرفر المدرسة (انظر `.env.example`).

للتعديل على الواجهة مباشرة:

```bash
# الطرفية 1
source .venv/bin/activate
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# الطرفية 2
cd frontend && npm run dev
```

واجهة التطوير تكون على [http://127.0.0.1:5173](http://127.0.0.1:5173) ومبنية بـ HeroUI.

## كيف تستخدمه

1. **الطلاب:** أضف اسم الطالب ورقمه وصفه وصورة أمامية واضحة لوجهه. الصورة الضعيفة تنرفض.
2. **الكاميرا:** اختر الصف والشعبة أولاً، اسمح للمتصفح يستخدم الكاميرا، وخلّ الطلاب يمرون قدامها.
3. **الحضور:** الإدارة تشوف الحاضر والغائب، تسجّل يدوياً عند الحاجة، وتصدّر إكسل فيه شيت لكل شعبة.
4. **الصفوف:** كل صف له شعبة ومقاعد.

أول مرة تضيف طالب أو تفتح الكاميرا، النظام يحمّل موديل التعرف (حوالي 100 إلى 200 ميجا). هذا يحصل مرة واحدة.

## كاميرا EZVIZ (RTSP)

الكاميرا مصدر صورة ثالث بجانب كاميرا اللابتوب ورفع الصورة، وتمر على نفس دالة التعرف (`recognize_image`). السيرفر يفتح اتصال RTSP واحد دائم، ويحتفظ بآخر إطار فقط في الذاكرة، ويعيد الاتصال تلقائياً. المتصفح ما يشوف رابط RTSP ولا الباسورد أبداً.

```bash
cp .env.example .env     # ثم املأ CAMERA_PASSWORD (رمز التحقق المطبوع على الكاميرا)
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

في صفحة «الكاميرا» اختر **كاميرا EZVIZ** والصف، ثم: **التقاط والتعرف** للقطة واحدة، أو **بدء التعرف التلقائي** (كل `FACE_RECOGNITION_INTERVAL_MS`). واجهات الـ API (كلها تحتاج تسجيل الدخول): `GET /api/cameras/ezviz/status`، `GET /api/cameras/ezviz/frame` (JPEG)، `GET /api/cameras/ezviz/stream` (MJPEG)، `POST /api/cameras/ezviz/recognize?classroom_id=`.

**مهم:** `192.168.0.100` عنوان شبكة محلية، فلازم السيرفر يشتغل على جهاز في نفس الشبكة. سيرفر سحابي ما يقدر يوصل للكاميرا بدون VPN. لا تشغّل أكثر من worker لأن كل worker يفتح اتصاله الخاص.

اختبار البث يدوياً من نفس الجهاز:

```bash
nc -zv 192.168.0.100 554
ffprobe -rtsp_transport tcp "rtsp://admin:<CODE>@192.168.0.100:554/ch1/main"
```

## البيانات والنسخ الاحتياطي

كل شيء محلي على نفس الجهاز. ما في سحابة ولا Convex: Convex خدمة سحابية وما تناسب سيرفر مدرسة ينقطع عنه النت أو الكهرباء.

القاعدة **SQLite** في `data/sahal.db` مع وضع WAL و`synchronous=FULL` حتى لو قطعت الكهرباء الكتابة تكتمل أو تترجع سليمة بعد التشغيل. الصور في `data/photos` والنسخ في `data/backups`.

نسخة يدوية:

```bash
source .venv/bin/activate
python -m app.backup
```

استعادة نسخة:

```bash
python -m app.backup --restore data/backups/sahal-YYYYMMDD-HHMMSS
```

النسخ القديمة تتنظف تلقائياً بعد 30 يوم (`SAHAL_BACKUP_KEEP_DAYS`). انسخ مجلد `data/backups` دورياً إلى USB أو قرص ثاني؛ النسخ على نفس الجهاز ما تحمي من تلف القرص.

يوم الحضور يتبع توقيت السيرفر (`SAHAL_TZ`، افتراضيًا توقيت الجهاز أو `Asia/Dubai` داخل دوكر). شاشة الحضور تستخدم نفس اليوم اللي الكاميرا تسجّل عليه.

## دوكر (للسيرفر)

ما تحتاج دوكر على جهاز التطوير. على سيرفر المدرسة بعد تركيب دوكر:

```bash
docker compose up -d --build
```

الموقع على المنفذ 8000. مجلد `./data` مربوط من الهوست: لو طفى الجهاز أو انقطع التيار، الداتا تبقى على القرص. خدمة `backup` تاخذ نسخة كل 24 ساعة داخل نفس المجلد.

بعد رجوع الكهرباء: `docker compose up -d` ويكمل من نفس الداتا بدون تركيب من جديد.

## ملاحظات

- الصورة لازم تكون أمامية وواضحة، ويفضّل وجه واحد فيها.
- الطالب ما ينسجل إلا مرة واحدة في نفس اليوم حتى لو مر أكثر من مرة.
- البيانات تتخزن محلياً في `data/sahal.db` والصور في `data/photos`.
- الكاميرا تشتغل من `localhost` بدون الحاجة لـ HTTPS.
